## 4. COMPLETE A2A TASK LIFECYCLE (CHECK 4)

The full protocol lifecycle was validated across both JSON-RPC 2.0 and REST endpoints:

```
[Agent Discovery] 
       │
       ▼
[Task Submission] ──> [Task Created: state="submitted"] 
       │
       ▼
[Runner Execution] ──> [Task State: state="working"]
       │
       ▼
[Status Query (tasks/get)] ──> Returns TASK_STATE_WORKING / TASK_STATE_COMPLETED
       │
       ▼
[Task Completion] ──> [Task State: state="completed"]
       │
       ▼
[Artifact Delivery] ──> Structured LearningAnalysisArtifact returned with telemetry
```

1. **Agent Discovery**: `GET /.well-known/agent-card.json` returns 200 OK with full agent capability card.
2. **Message Submission**: Supported via JSON-RPC `message/send` (or `send_message`) with `parts` array and metadata.
3. **Task Creation**: Implemented in `A2ATaskStore.create_task()`, generating `a2a_task_<hex12>` in state `submitted`.
4. **Task Status Retrieval**: Handled by JSON-RPC `tasks/get`, returning standard `task.status.state` (`TASK_STATE_SUBMITTED`, `TASK_STATE_WORKING`, `TASK_STATE_COMPLETED`, `TASK_STATE_FAILED`).
5. **Task Completion**: `A2ATaskStore.set_completed()` updates state, records execution duration, and binds the artifact.
6. **Artifact Delivery**: Returns structured `LearningAnalysisArtifact` containing identified patterns, misconceptions, weaknesses, priorities, confidence, and recommendations.
7. **Error Response**: Evaluated with standard JSON-RPC 2.0 error codes (`-32700` parse error, `-32600` invalid request, `-32601` method not found, `-32001` auth/isolation error) and HTTP status codes (400, 401, 403, 503, 504).

## 9. DOCUMENTED LIMITATIONS & REMAINING GAPS

1. **Protobuf `AgentCapabilities` Field Discrepancy**:
   The generated Agent Card dictionary contains `"capabilities": {"tasks": true, ...}`. The compiled Protobuf message `lf.a2a.v1.AgentCapabilities` defines `['streaming', 'pushNotifications', 'extensions', 'extendedAgentCard']`. While standard JSON-RPC clients consume the card without issue, strict Protobuf deserializers require `ignore_unknown_fields=True`.
2. **Client Port Resolution**:
   In `backend/a2a_protocol/client.py`, the TCP socket check inspects `port = 8000`. If the server runs on a non-standard port other than 8000 without explicitly matching `:8000` in the URL, the client defaults to ASGI in-process transport.
3. **In-Memory Task State Store**:
   `A2ATaskStore` maintains task records in memory (`self._tasks = {}`). Active task records reset if the backend server process restarts. Persistent database task backing is appropriate for future production scaling.
4. **Local Ollama Daemon Offline**:
   During audit testing, the local Ollama service (`127.0.0.1:11434`) was offline. The ADK Runner caught the LiteLLM connection refusal and successfully invoked bounded deterministic fallback synthesis (`synthesize_deterministic_learning_artifact`), or raised HTTP 503 when fallback was disabled. Full live LLM inference requires a running Ollama daemon.
